# Адаптация LUMÉ Riviera под клиента

Этот документ — технический чек-лист. Фактические реквизиты и решения сначала
фиксируются в `CLIENT-QUESTIONNAIRE.md`, затем переносятся в
`site.config.json`.

## 1. Сделать отдельную ветку

Для каждого потенциального покупателя создавайте отдельную ветку. В `main`
оставляйте чистую демоверсию. Предпросмотр ветки должен быть закрыт от
индексации и, если в нём есть непубличные материалы клиента, от постороннего
доступа.

## 2. Заполнить конфигурацию

Основной файл — `site.config.json`. Не помещайте туда пароли, API-ключи,
секреты платёжных систем, доступы к CRM или персональные данные посетителей.

Обязательные блоки:

| Блок | Что изменить |
|---|---|
| `business` | бренд, юридическое имя, публичные контакты, адрес, карта, часы |
| `booking` | один способ записи и его параметры |
| `features` | нужные разделы и переключатель валют |
| `pricing` | базовая валюта, коэффициенты и правила округления |
| `seo` | итоговый HTTPS-домен, заголовки, описания, изображение |
| `services` | услуги, категории, цены, длительность и четыре перевода |

Номера WhatsApp в конфигурации записываются только цифрами, например
`905551112233`. Телефон может начинаться с `+`.

## 3. Выбрать способ записи

| `booking.adapter` | Когда использовать | Что заполнить |
|---|---|---|
| `whatsapp` | малый салон, запись подтверждает администратор | `business.whatsappNumber` |
| `external` | у клиента уже есть проверенный сервис записи | `booking.externalUrl` |
| `phone` | запись только звонком | `booking.phone` или `business.phone` |
| `disabled` | публичное портфолио без настоящих заявок | ничего |

Для `external` сайт добавляет идентификатор услуги в HTTPS-ссылку. Имя
параметра задаётся в `serviceQueryParameter`.

Не вставляйте в статический сайт секретный API-ключ внешнего сервиса. Если
провайдер требует секрет, интеграция должна идти через его официальную
страницу бронирования либо отдельный серверный посредник.

## 4. Заменить контент и изображения

- заменить логотип, favicon, hero и галерею;
- проверить права на каждую фотографию и письменное согласие людей в кадре;
- удалить вымышленные отзывы либо заменить их подтверждёнными;
- проверить цены, длительность, часы, адрес и языки обслуживания;
- обновить тексты FAQ и правила отмены записи;
- оптимизировать новые изображения в WebP/AVIF без метаданных геолокации.

Файлы изображений, перечисленные в `sw.js`, должны существовать. После замены
кэшируемых HTML, CSS, JavaScript или изображений увеличьте версию `CACHE` в
`sw.js`. Конфигурация проверяется в сети при каждом открытии и имеет безопасную
офлайн-копию.

## 5. Обновить статические метаданные

После изменения конфигурации выполните:

```bash
npm run build:lume:metadata
```

Команда синхронизирует первоначальные title, description, canonical, Open
Graph, JSON-LD и его CSP-хэш, а также `manifest.webmanifest`, `sitemap.xml` и
`robots.txt`. Это важно: социальные роботы не обязаны исполнять JavaScript,
поэтому одной динамической замены метаданных в браузере недостаточно. Размеры и
кадрирование изображения для социальных сетей всё равно нужно проверить
вручную.

Разметка LocalBusiness должна описывать только реальные сведения, видимые на
странице. Перед запуском проверьте её в Google Rich Results Test.

## 6. Подготовить юридические страницы

Получите утверждённые клиентом ссылки на политику конфиденциальности и, если
применимо, условия записи/отмены. Сайт намеренно не содержит универсального
юридического текста: требования зависят от страны бизнеса, клиентов,
аналитики, рекламы и поставщиков.

Минимально зафиксируйте:

- кто является оператором данных и как с ним связаться;
- какие данные получает WhatsApp или внешний сервис;
- цели, основание и сроки хранения;
- получателей, трансграничную передачу и права пользователя;
- порядок удаления/исправления данных;
- правила отмены, возврата и предоплаты.

При добавлении аналитики или маркетинговых пикселей сначала определите
правовое основание и механизм согласия, затем обновите CSP и документацию.

## 7. Домен и хостинг

- использовать HTTPS и автопродление сертификата;
- включить MFA у регистратора, хостинга и GitHub;
- дать клиенту собственный аккаунт владельца домена;
- ограничить права команды минимально необходимыми;
- включить защиту переноса домена и проверить контакты восстановления;
- настроить отдельный закрытый preview для каждой ветки/PR.

Cloudflare Pages создаёт отдельные preview URL для веток и pull request. Если
в превью есть непубличные данные, доступ можно ограничить Cloudflare Access.

## 8. Переключить production

Последним изменением установите:

```json
"mode": "production"
```

Автопроверка остановит запуск, если нет юридического имени, адреса, публичного
контакта, HTTPS-политики конфиденциальности, клиентского домена или рабочего
канала записи. В браузере незаполненная production-конфигурация также блокирует
переход к записи.

## 9. Проверить перед релизом

Выполнить команды из `README.md`, затем вручную проверить:

- четыре языка и все услуги;
- мобильное меню, клавиатурную навигацию и видимый фокус;
- запись для каждого типа услуги;
- итоговый адресат WhatsApp/телефона/внешней системы;
- ссылки политики и условий;
- карту, email и домен;
- отсутствие настоящих данных клиента в preview;
- отсутствие ошибок CSP и JavaScript в консоли;
- страницу 404 и поведение без сети.

После публикации провести внешний DAST-скан только с письменным разрешением
владельца домена и в согласованное окно.
